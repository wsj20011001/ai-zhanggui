## 1. 主路径（4 分钟，四镜头）

### 镜头一 · 它只给你三件事（40 秒）
**页面**：`/admin/ai`

| 你的动作 | 你说的话 |
|---|---|
| 停在驾驶舱，不做操作 | 「中小餐饮老板每天早上要回答三个问题：今天赚没赚、明天买多少、哪道菜在赔钱。现在市面上的工具给他更多报表——我们给他三个动作。」 |
| 鼠标从左到右划一遍三张卡 | 「按轻重缓急排序，先红后黄，不是按模块罗列。第一，昨天营收比同星期低了 31%。第二，基围虾只够 1.5 天。第三，近 7 天毛利率 57%，低于目标。」 |
| **点第一条的「定位原因」** | 「注意它没停在『跌了』。」 |

**屏幕应出现**：拆解面板，显示营收变化 **−3,390 元**，其中**客流 −3,934**、**客单价 +543**。

| 你的动作 | 你说的话 |
|---|---|
| 指着「客流影响」那一行 | 「营收 = 单数 × 客单价。它拆成两块：客流少了 15 桌，客单价反而涨了 20 块，净下来 −3,390。**结论是人少了，不是点便宜了**——一个要查排班和天气，一个要查高单价菜是不是断货，解法完全不同。」 |

### 镜头三 · 数字不是模型说的（50 秒）
**页面**：侧栏「经营问答」`/admin/ai/chat`

| 你的动作 | 你说的话 |
|---|---|
| 输入框打：`上周哪道菜毛利最高`（直接粘贴，别现场打字），回车 | 「它生成的不是一段话，是一条 SQL。」 |
| 等结果（**1–2 秒**），指结论 | 「结论、图表、行数，一次给全。」 |
| **点开「查看这条结论用到的 SQL」** | 「只能查 8 个只读视图，看不到会员手机号，改不了数据，最多 500 行，6 秒超时。」 |
| 用鼠标框一下 `FROM v_` 那一段 | 「所以它不会算错账——**因为它不算账**。数字是 SQL 算出来的，模型只负责把问题翻译成查询、把结果翻译成人话。」 |
| （可选，加分）| 「而且我们会核对结论里的数字：数量对不上行数、金额不在结果里，就判定为编造，直接换成确定性摘要。这是我们在接入真模型后被咬过的地方——它把『9 种』说成『6 种』、把 2.8 斤写成 3.2 公斤。」 |

## 3. 故障应对（背下来，别慌）

| 现象 | 你的一句话 | 手上怎么做 |
|---|---|---|
| 提问转圈超过 **15 秒** | 「云端超时了，它会自动降级——」 | 继续等。它会先试本地模型，本地也不行才降到规则模式（实测最坏约 18 秒，别当场排查） |
| 徽标变「规则模式」 | 「网络不稳，我们自动切到本地规则引擎，答案变成模板化的，但不会中断。」 | 继续演，别排查 |
| 页面点乱了 / 数据被改 | 「演示数据可以一键还原。」 | 别当场还原，继续讲；审核结束再 `reset_demo.py --restore` |
| 浏览器打不开 | 「稍等，服务在启动。」 | 重开一次页面；还不行就切 PPT 讲架构 |
| 彻底跑不起来 | 「我直接用材料讲。」 | 翻 PPT 第 4–6 页讲能力与架构，**不要反复重启** |

## 4. 八个必答问题（照这个口径说）

| 问题 | 答（30 秒内） |
|---|---|
| 商业模式？ | 单店免费版（离线、只读分析），连锁版按门店数订阅。获客靠收银系统存量客户。 |
| 数据哪来的？ | 模拟数据，但按星期效应、节假日、雨天、菜品帕累托分布合成，成本按 38% 成本率校准，脚本固定种子可复现。 |
| 为什么不用大模型做预测？ | 单店 180 天数据撑不起。用水平 × 星期因子 × 趋势，回测误差 32% 直接放在页面上。 |
| 建议有没有效？ | **没验证。** 只做了留痕和可撤销。原来那版会无条件写 effective，我发现后改成了 unverified。真正的因果归因要对照组。 |
| 能连锁吗？ | 不能。要全表加 `store_id` 并回填，约 15 人日，而且必须先解决成本口径。 |
| 改了进价，历史毛利会变吗？ | 会。成本按当前配方算，还没版本化——这是已知口径缺口。 |
| 和餐饮 SaaS 什么区别？ | 他们做记录，我们做决策和执行。不替换收银，长在它上面。 |
| 最难的是什么？ | 不是技术，是让老板每天愿意点开那三件事。所以首屏只放三条，每条都能一键执行。 |
