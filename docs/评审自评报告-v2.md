## 1. 技术先进性与问题解决能力 · 26 / 30

### 1.1 AI 技术应用深度 · 11 / 12（+1）

| 要点 | 证据 | 评价 |
|---|---|---|
| 超越简单 API 调用 | `ai/sandbox.py` 五道闸；`ai/nl2sql.py` 受控查询 + 自修复一轮 + 降级 | 达标有余 |
| Prompt 工程 | `VIEW_DOC` 写入口径；「数字纪律」9 条硬约束；few-shot 用真实日期 | 明显高于模板级 |
| 自研算法 | 三层分解预测 + 滚动回测；营收二因素分解；6 类检测器；四象限 | 经典统计，非创新但扎实 |
| 结论级数字校验 | 数量词 = 行数/去重值；金额 ∈ 结果集；**空结果一律判定为编造**（v2 新增） | 最有辨识度的技术点 |
| 可复现评测 | `tests/eval_nl2sql.py` 12 题 100%，1195ms，自动生成报告 | 少见 |
| **三通道实装** | 本地 qwen2.5-3B 真跑通（2.0GB，CPU 30 tok/s）、云端 DeepSeek 1.2s、规则 <50ms | v2 从"声称"变为"可现场验证" |

**仍扣 1 分**：没有微调；工具选择是确定性分发（`action_type` → if/elif），
不是让模型自由选。**这一条已在 README 里改成如实描述**——
从"夸大的亮点"改成了"刻意的设计选择（3 个动作可控 vs 30 个动作不可预测）"。

### 1.2 技术突破性 · 8 / 10（+1）

**加分**

- 结论级数字校验：多数 NL2SQL 只保证"SQL 能跑"，这里保证"结论里的数字对得上表"；
- 三通道降级不是 PPT 概念：本地模型真实拉起、真实回答、真实测速；
- 踩过并写进 ADR 的坑：系统代理劫持 `127.0.0.1` 导致 502、Windows 上 `SO_REUSEADDR` 让端口探测失效、
  取号表缺失导致首单撞号——这三条都是"只有真跑过才会遇到"的工程细节。

**扣分**：仍无技术壁垒；预测是标准三层分解，回测误差 32%。

### 1.3 问题针对性与有效性 · 7 / 8（不变）

三问三页面、动作闭环（生成→确认→入库→流水→可撤销）都成立。
**扣 1 分不变**：`settle_actions` 已不再伪造 `verdict='effective'`（v2 修正），
但"建议是否有效"仍然没有因果验证——只是现在**诚实地说没有**，而不是假装有。

## 2. 方案成熟度与工程质量 · 33 / 35（+4）

### 2.1 可运行性与功能完整性 · 10 / 11（+1）

点餐端三个真实缺陷已修（v2）：

| 缺陷 | 修复 | 验证 |
|---|---|---|
| 改人数只重绘不落库，`persons` 恒为 1 | 变化后 400ms 防抖 `saveCart()` | `test_mobile.py`：3 vs 3 |
| 整单备注只改内存变量 | 失焦即落库 | 备注回读一致 |
| 催菜只允许 `pending` | 放开 `making` | pending/making 可催，done 拒绝 |

**额外发现（v2 最重要的一处）**：`make_order_no` 首次取号时计数表可能为空，
当天第一单会生成 `0001` 与演示数据撞车 → **下单直接 500**。
现场演示点第一单就会炸。已修：首次取号从当天已有单号最大值回填。
实测下单返回 `D20261022-0011 / persons=4 / 备注落库`。

**仍扣 1 分**：效果回流功能缺失（已从材料撤下，不再宣称）、无定时任务与自动备份。

### 2.2 代码质量与工程规范 · 9 / 9（+1）

v1 指出的三处"文档与实现不一致"**全部修正**：

| 原表述 | 现表述 |
|---|---|
| "AST 级校验" | "只读连接、视图白名单、危险模式校验、强制 LIMIT、超时中断" |
| "`store_id` 字段已预留" | "未实现，预估 15 人日，且必须先解决成本口径" |
| "7 天后回填效果，判定有效/无效" | 代码改为 `unverified`，材料列入"已知边界" |
| （v2 追加）"模型只负责选工具、填参数" | "由 `action_type` 确定性分发" |

另外：30 次语义化提交、LICENSE（含第三方声明）、`docs/技术说明.md`（11 条 ADR）、
`run_tests.py` 一键入口。分层纪律与迁移体系保持 v1 水平。

### 2.3 系统架构与健壮性 · 7 / 8（+1）

v2 修掉两个**崩溃级**问题：

- 取号撞号（并发计数表 + 历史回填）；
- Windows 端口探测（`connect` 代替 `SO_REUSEADDR + bind`，否则两个实例抢同一端口）。

加上原有的三层降级、SQL 超时中断、动作幂等、统一错误页、WAL + busy_timeout。

**仍扣 1 分**：购物车全量覆盖无并发控制（连点可能丢数量）、可用份数只看当前库存
（下单到出餐窗口内多桌会看到同样的"还可做 N 份"）。

### 2.4 数据安全与测试覆盖 · 7 / 7（+1）

v1 的最大扣分项——"点餐端与 `/api/*` 零覆盖"——已补：

```
8 个套件 · 26 秒 · 全绿
页面 22/22 · 沙箱 8/8 · 口径 5 处 · CSV 导入 · 点餐端 12 项
本地通道 9 项 · Mock 链路 · 单元 50 项 · NL2SQL 评测 12 题
```

加上原有的 pbkdf2 + 自动升级、会话固定防护、CSRF 全站注入、Key 独立文件、
模型只能看 8 个聚合视图。

## 7. 现场答辩口径（v2 更新）

| 问题 | 建议答法 |
|---|---|
| 你怎么证明建议有效？ | 「没证明。我们只做了留痕和可撤销，`verdict` 字段我们改成了 `unverified`——原来那版会无条件写 effective，我发现后改掉了。真正的因果归因要对照组，规划里。」 |

| 本地模型是装的还是编的？ | 「真装了。qwen2.5-3B Q4，2GB，纯 CPU 30 token/s。设置页点『测试本地模型』能现场看到它回答。质量不如云端，所以默认走云端、断网切本地。」 |
