# 部署与成本说明

> 面向"落地可行性"评审：这家店要花多少钱、多久能上线、断网怎么办。

---

## 1. 三种部署方式

| 方式 | 适用门店 | 耗时 | 说明 |
|---|---|---|---|
| **本机直跑** | 有 Windows 电脑的店 | 5 分钟 | 双击 `start.bat`，自动建虚拟环境并启动；浏览器打开 `127.0.0.1:5100` |
| **打包 EXE** | 不想装 Python 的店 | 10 分钟 | `build.bat` 用 PyInstaller 打包（配置见 `build.spec`），生成单文件 EXE |
| **局域网服务器** | 多台点餐终端 | 30 分钟 | 一台普通 PC 作服务端，平板/手机连同一 WiFi 打开 `http://<内网IP>:5100` |

推荐：**收银那台电脑直接跑**。不新增设备，数据留在店里。

---

## 2. 硬件与成本

| 项目 | 要求 | 成本 |
|---|---|---|
| 电脑 | 任意 Win10/11，4GB 内存即可（无 GPU 要求） | 复用收银机，0 元 |
| 存储 | 180 天数据约 5MB；一年约 20MB | 忽略不计 |
| 网络 | **可断网运行**；接云端模型时只需普通宽带 | 0 元 |
| 云端模型（可选） | DeepSeek 等 OpenAI 兼容 API | 见下 |
| 软件许可 | 本项目 MIT，第三方仅 Bootstrap / ECharts | 0 元 |

### 云端模型成本（可选）

按单次问答 输入约 1.2k token、输出约 150 token 估算：

- 单次成本约 **0.1–0.3 分钱**（按各家现价，以官方价目表为准）；
- 每天 30 次问答 ≈ **1–3 元/月**；
- 不接云端也能用（规则模式），成本为 0。

> 这一项的意义不是省钱，而是**让门店可以按需选择**：在意数据就本地跑，在意效果就接云端。

## 3. 上线流程（一周）

| 天 | 事项 | 谁做 |
|---|---|---|
| D1 | 装系统、导入历史订单（CSV） | 实施 |
| D2 | 对齐菜名与配方（BOM），校准食材成本 | 店长 + 实施 |
| D3–D4 | 并行跑：系统建议 vs 店长决策，记录差异 | 店长 |
| D5 | 调阈值（毛利率目标、库存预警天数、折扣上限） | 实施 |
| D6–D7 | 只读演示 → 开始采纳建议，观察采纳率 | 店长 |

**最难的不是技术，是让老板每天愿意点开那三件事。** 所以我们把首屏压到 3 条，
且每条都能一键执行——降低"看了但不动"的概率。

## 4. 数据与安全

| 项 | 做法 |
|---|---|
| 数据存放 | 单文件 SQLite，存门店本机，默认不上传 |
| 模型可见范围 | 只有 8 个聚合视图；看不到会员手机号、口令、设置表 |
| API Key | 存独立文件 `data/ai_key.txt`，不入库、不进日志、不打进备份包 |
| 备份 | 后台「数据备份」一键导出；`reset_demo.py` 可恢复到初始快照 |
| 审计 | 所有写操作记 `op_logs`；AI 动作额外记 `ai_actions`（含 before 快照） |
| 外网暴露 | 默认仅局域网；如需外网，前置 HTTPS 反向代理 |

---

## 5. 运维

| 场景 | 操作 |
|---|---|
| 每天 | 无需维护（无定时任务） |
| 每周 | 后台看一眼「操作日志」，确认无异常写入 |
| 每月 | 导出一份备份到 U 盘/网盘 |
| 升级 | 覆盖代码目录，`data/restaurant.db` 不动；启动时自动迁移表结构 |
| 故障 | 页面报错会显示错误码与出口链接；日志在控制台窗口 |

---

## 6. 边界（写清楚，避免过度承诺）

1. 单店形态，多门店需要加 `store_id` 维度（表结构已预留设计，未实现）；
2. 需要门店有可导出的订单数据（CSV 或直接读库）；
3. 配方（BOM）必须录入，否则成本与毛利算不出来——这是实施的主要工作量；
4. 不替代收银系统，是长在它上面的一层。
